# phantom — пространственная C++ IDE

Настольное приложение на Electron с настоящим терминалом, сборкой и запуском C++, редактором и отдельным 3D-представлением кода. Старый проект `../my_idle` не изменён.

## Совместная разработка: macOS и Linux

Репозиторий: [Tigersmechom/Phantom](https://github.com/Tigersmechom/Phantom). Ветка `main` содержит текущий интерфейс и общие договорённости; `backend/linux` — подготовку отдельного C++20-бэкенда для Linux. Проверенное настольное приложение пока собрано для macOS; наличие Linux-ветки не означает, что весь Electron-интерфейс уже проверен на Linux.

Основное задание и приоритеты — [docs/BACKEND_HANDOFF.md](docs/BACKEND_HANDOFF.md). Для backend-агента: [инструкция Linux в ветке backend/linux](https://github.com/Tigersmechom/Phantom/blob/backend/linux/docs/LINUX_BACKEND.md). Работа над необычной историей исполнения, вычислениями, временем жизни и памятью идёт раньше Codeforces, графов и многопоточности.

```sh
git clone git@github.com:Tigersmechom/Phantom.git
cd Phantom
git switch --track origin/backend/linux
```

Бэкенд собирается независимо от Electron/Node.js. Для него не нужно копировать с Mac `node_modules`, `.app`, `release`, `.frame/build` или кэши Unreal. Исходники, общие типы и примеры уже находятся в репозитории. macOS- и Linux-исполнители должны отдавать один версионируемый протокол; пользовательская программа исполняется в явно указанной среде.

## Запуск

Откройте **`release/phantom-darwin-arm64/phantom.app`** или дважды нажмите **`Start.command`**. Скрипт открывает приложение с этой папкой в качестве проекта. Готовая `.app` содержит Electron и не требует отдельного Node.js для запуска; для компиляции нужны Xcode или Command Line Tools.

В приложении можно открыть файл C++ или папку проекта. Последний проект запоминается. Сохранение — `Cmd+S`; при закрытии и перезагрузке окна несохранённый исходник можно сохранить, отбросить или оставить открытым. Настройки прежней FRAME переносятся в профиль phantom без перезаписи уже существующих настроек.

## Сборка и выполнение

**Basic** действительно сохраняет текущий исходник, компилирует его для выбранной ARM64/x86-64 и запускает полученный файл. Поле STDIN передаётся программе, затем ввод закрывается. STDOUT, STDERR и код завершения приходят от процесса. Кнопка остановки завершает программу.

`Cmd+B` только собирает файл. `Cmd+Enter` запускает выбранный режим. Результат сборки и команда компилятора находятся во вкладке **«Сборка»** под редактором.

В **Настройки → «Сборка»** находится одно поле флагов: по одному аргументу на строку, без shell-кавычек. Изменения автоматически сохраняются при потере фокуса или закрытии настроек. Отдельной кнопки сохранения нет; статус и ошибки показаны под полем.

Конфигурация хранится в **`.frame/build.json`** проекта; путь сохранён для совместимости:

```json
{
  "version": 1,
  "compiler": "/usr/bin/clang++",
  "flags": ["-std=c++20", "-g", "-O0", "-Wall", "-Wextra"],
  "outputDirectory": ".frame/build"
}
```

Компилятор и каталог результата при необходимости меняются в JSON. Компилятор вызывается напрямую; исходник, `-arch` и путь результата добавляет phantom. Каталог результата должен находиться внутри проекта. Запуски ограничены 120 секундами и 4 МиБ вывода; достижение ограничения явно отмечается.

## Терминал и панели

**Ctrl + обратная кавычка** открывает настоящий PTY-терминал под кодом. Оболочка запускается в папке проекта; работают `cd`, `ls`, история, интерактивные программы и `Ctrl+C`. Скрытие панели сохраняет сессию и вывод. При смене проекта новая сессия открывается в его папке.

Кнопка с корзиной завершает старую оболочку и её дочерние процессы, очищает экран и открывает новую сессию в папке проекта. Изменённые через `export` переменные старой сессии не переносятся.

Границы редактора, переменных, stdin/stdout и нижней панели перетягиваются мышью. Разделители также доступны с клавиатуры.

## Оформление и 3D

Темы **Obsidian**, **Porcelain**, **Spectral**, гарнитура, размер и рельеф находятся только в **настройках**. Размеры текста кода, ввода и вывода регулируются отдельно; числа и названия в дебаггере имеют независимые масштабы. Там же меняются глубина и свет 3D-букв, яркость активной полоски, каркас и слежение камеры. Настройки и размеры панелей сохраняются.

Изменения значений, области выполнения и вывода анимированы. Числа быстро увеличиваются почти до доступных границ ячейки и плавно возвращаются; размер импульса учитывает длину значения и масштаб текста. Камера плавно разгоняется, останавливается и переходит между строками и функциями.

В **Настройки → «3D и камера» → «Результаты вычислений»** доступны три расположения: **«Над выражением»**, **«На полях»** и **«В плоскости»**. Значения привязаны к диапазонам исходника и следуют за камерой. В ручном режиме операнды сходятся к результату; при воспроизведении показывается итог. Предыдущая подсказка плавно исчезает при переходе к следующей. Плашки обходят буквы; если безопасного места нет или выражение вне кадра, подсказка скрывается.

**«На полях» (rail)** выбран для новых настроек по умолчанию. Аргументы вызова показаны в отдельных цветных рамках с подписями и толстыми пунктирными указателями к каждому операнду. Между числами арифметических и логических операций виден фактический знак C++; подтверждённые логические результаты отображаются как `true`/`false`. У ручной анимации есть пауза для чтения перед медленным слиянием. Сохранённый выбор расположения остаётся прежним.

Инспектор показывает текущий кадр функции: при входе в `add` видны аргументы `a` и `b`, при возврате — переменные `main`. Локальные данные вызывающей функции не смешиваются с параметрами вызванной; история восстанавливает соответствующий кадр.

Переключатель **«Код / 3D»** меняет представление исходника. В 3D мышь вращает камеру, прокрутка меняет масштаб, стрелки перемещают её; `Shift` ускоряет движение. При включённом слежении камера возвращается к активной строке через **2 секунды без ручного ввода**. Сейчас активная строка поступает из отладочного примера; Basic не создаёт пошаговых остановок. Ввод текста выполняется в обычном редакторе.

Цвета синтаксиса и активного выделения извлечены из установленных тем **Xcode Default Dark/Light** в `src/xcode-palette.json`. Выделение совпадает с геометрией символов, а рельеф выделенных букв убирается для читаемости. Для неактивного выделения используется нейтральный цвет: соответствующего поля в исходных темах Xcode нет. Подсветка C++ пока лексическая.

Monaspace Neon/Krypton включены локально с лицензией SIL OFL. 3D использует Droid Sans Mono; уведомления находятся в `public/fonts`. SF Mono выбирается из системных шрифтов. Повторное извлечение палитры: `python3 scripts/extract-xcode-palette.py`.

## Что остаётся демонстрацией

**Debug, переменные, история, точки остановки и hover ASM — явно обозначенный demo**, не данные LLDB. Подготовленный trace содержит **57 кадров** именно `DEMO_SOURCE`: объявления, выделение массивов, ввод каждой ячейки, проверки и приращения цикла, вызовы `add`, вычисления, записи результата, вывод и возврат. `F10` / `Shift+F10` меняют кадры; скорость воспроизведения в верхней панели — **0,25–12 операций/с**. Изменённый произвольный C++ этот trace не исполняет.

До появления значения интерфейс показывает **NaN** как заглушку недоступности (`null` в модели). Созданные `vector<int>(n)` и `vector<int>(n + 1, 0)` сразу содержат настоящие нули. Подсказки вычислений в 3D показывают готовые операнды и результат события; они не вычисляют C++ из текста.

В STDIN рамка выделяет следующий фрагмент `cin`, а тонкая полоса отмечает прочитанные значения. Диапазоны относятся к точному отправленному тексту, включая пробелы и переносы. Редактирование ввода скрывает прежние отметки до нового запуска. Сейчас эти наблюдения даёт только подготовленный trace; Basic передаёт stdin процессу, но не наблюдает извлечения `cin`.

Наведение на номер строки на одну секунду открывает макет ASM выбранной архитектуры; он не связан с собранным бинарником.

Следующий этап — самостоятельный Linux-бэкенд C++20 с адаптерами отладчика, записью исполнения и семантической инструментацией. Старый backend первой версии можно изучать как необязательный read-only пример; он не нужен для клонирования и сборки нового проекта. Текущие границы описаны в [docs/INTEGRATION.md](docs/INTEGRATION.md), контракт и задание для независимого backend-агента — в [docs/BACKEND_HANDOFF.md](docs/BACKEND_HANDOFF.md). Типы будущего адаптера находятся в `src/backend-contract.ts`; это ещё не подключённый debugger IPC.

Основная передача изменений теперь выполняется через Git-ветки. Старый **`release/phantom-backend-source.zip`** с `BACKEND_BASELINE.json` остаётся прежним baseline для сравнения ранее сделанных изменений. Существующий `npm run handoff:backend` создаёт пакет прежнего состава и не включает новый C++-бэкенд; для новой Linux-разработки нужен Git clone ветки `backend/linux`. Не перезаписывать архивный baseline при синхронизации веток.

В [unreal/README.md](unreal/README.md) — отдельный проект Unreal 5.8.2 с сохранённой Text3D-сценой. Генерация карты проверена; offscreen-захват дал чёрный кадр, поэтому готового Unreal-превью пока нет.

## Разработка и проверки

```sh
npm install
npm run rebuild:native
npm run dev:desktop
```

```sh
npm run build
npm start
npm run package:mac
npm run test:native
```

`npm run package:mac` создаёт `release/phantom-darwin-arm64/phantom.app` и архив `release/phantom-macOS-arm64.zip` с проверенной ad-hoc подписью для локального запуска. Native-проверки используют настоящий компилятор, ARM64/x86-64, PTY, перезапуск оболочки, stdin, остановку процессов и сохранение при закрытии. Проверка trace: `node --test tests/demo.test.mjs`.

Для отдельного браузерного просмотра: `npm run dev -- --port 5173`. В нём нет системного терминала и native-сборки. UI-проверки с запущенным сервером: `npm test`, `npm run test:editor`, `npm run test:spatial`.

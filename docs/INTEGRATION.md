# Исполнение и дальнейшая интеграция

phantom — Electron-приложение: сборка `release/phantom-darwin-arm64/phantom.app`, архив `release/phantom-macOS-arm64.zip`. `Start.command` открывает приложение с текущей папкой проекта. Первый проект `/Users/123/Desktop/my_idle` не изменён.

Для отдельного backend-агента основной документ — **[BACKEND_HANDOFF.md](BACKEND_HANDOFF.md)**: текущие и предложенные API, DTO v1, границы наблюдений, IO/выражения, история, критерии приёмки и работа в отдельной копии с последующим merge. Типы `src/backend-contract.ts` пока являются контрактом будущего адаптера; существующий native bridge не объявлен LLDB-реализацией.

## Реализованная native-граница

`electron/main.cjs` создаёт окно с `contextIsolation`, sandbox и отключённым Node.js в renderer. Узкий `window.frameNative` из `electron/preload.cjs` описан в `src/native.ts`; IPC проверяет отправителя и главное окно приложения.

Внутренние имена `frameNative`, `FRAME_*` и путь `.frame/build.json` сохранены для совместимости. `profile-service.cjs` один раз копирует отсутствующие persistent-настройки и последний проект из профиля FRAME в phantom, сохраняя старый профиль и существующие новые настройки.

- `getWorkspace`, `openFile`, `chooseWorkspace`, `saveDocument` работают с реальными файлами и выбранной папкой.
- `saveBuildConfig` сохраняет `.frame/build.json`: `version`, `compiler`, массив `flags`, `outputDirectory`. В UI — только textarea флагов, один аргумент на строку, автосохранение при blur/закрытии настроек. Сборка дожидается сохранения и добавляет исходник, архитектуру и `-o`; компилятор и каталог задаются в JSON.
- `compile` сохраняет код и запускает компилятор через `spawn` без shell, с cwd проекта. Возвращает точную команду, stdout/stderr, код завершения и путь результата.
- `execute` запускает последний успешный результат отдельным процессом с фиксированным stdin и EOF. `stopExecution` останавливает его. **Basic использует именно этот путь.**
- `terminal` управляет настоящим `node-pty`; `TerminalPanel` отображает поток через xterm. Ctrl + обратная кавычка скрывает панель, сохраняя оболочку и буфер. `terminal.restart({cols,rows})` и `TerminalPanel.resetKey` завершают старую оболочку с дочерними процессами и создают чистую сессию в cwd проекта; экран и очередь ввода сбрасываются.
- `updateDocumentState` хранит несохранённый текст в main-процессе без записи на диск. Закрытие, Cmd+Q и перезагрузка окна предлагают сохранить, отбросить или отменить действие. Отмена оставляет процессы работающими; после подтверждённого выхода они завершаются.

Изменение сохранённого исходника/конфигурации, неудачная сборка и смена проекта делают прежний результат недоступным для нового запуска до успешной компиляции. Вывод ограничен 4 МиБ, длительность сборки/запуска — 120 секундами; причины остановки возвращаются явно. Нативные проверки находятся в `tests/native-project.mjs` и `tests/native-electron.mjs`.

## Renderer

Темы, шрифты, рельеф, глубина, свет, яркость полоски и параметры камеры находятся в настройках. Размеры кода/stdin/stdout и масштабы чисел/названий дебаггера независимы и сохраняются. Активное выделение использует цвет темы Xcode и совпадает с символами; неактивный цвет — нейтральный fallback. Изменения значений, области и вывода анимируются.

Жизненный цикл отображения отделён от состояния выполнения. `InspectorScope` принимает
явный `transition`: `forward` с `departedFrame`, `departedVariables` или `retiredArrays`
запускает конечную сцену завершения; `seek` очищает её без имитации смерти. Поэтому
пропавшее поле само по себе не считается уничтоженным. Данные об инвалидированном
указателе или ссылке показываются как «зомби» только при переданном `lifetime.state`.
`src/presentation-motion.tsx` даёт общий ограниченный по времени координатор: в режиме
`BASE` renderer ждёт самую длинную зарегистрированную сцену и добавляет 500 мс, а `RATE`
сохраняет независимый таймер операций. Эффекты не меняют историю; reduced motion
отключает декоративные переходы.

Редактор и 3D-представление получают общий исходник. Стрелки плавно двигают камеру, Shift ускоряет её; слежение возвращается через 2 секунды покоя после ручного управления. Камера следует за кадром Debug demo; Basic не предоставляет отладочную позицию. Скорость demo регулируется в верхней панели: 0,25–12 операций/с.

`src/demo.ts` содержит 57 подготовленных кадров только `DEMO_SOURCE`, включая объявления, поэлементный ввод, условия/приращения, вызовы/возвраты, запись, cout и return. Недоступные значения — `null`, в инспекторе отображаются как NaN; реальные нули после инициализации векторов сохраняются нулями. Вывод появляется на cout, завершение — на следующем return. Контракт проверен в `tests/demo.test.mjs`.

Одна точка истории имеет одинаковые значения при движении в обе стороны: `values` недоступен до кадра с индексом 2, `prefix` — до индекса 16; после их создания известные нули не превращаются в NaN. Проверки проходят все 57 кадров вперёд/назад и границы выделения. UI отображает только выбранную активацию и действующие области: в `add` — его аргументы, без автоматического показа locals вызывающей `main`. Будущий backend передаёт это через stack/activation/scope IDs, не восстанавливает из номера строки.

`src/execution-types.ts` задаёт `ExpressionEvent`: готовые операнды, оператор, результат, цель и необязательные диапазоны исходника. Будущий backend передаёт `groups` в наблюдаемом порядке; порядок стадий внутри группы не предполагается. Renderer показывает предоставленный результат и не угадывает порядок вызовов, ассоциативность или вычисление произвольного C++ по тексту.

## Следующий этап: отдельный Linux-бэкенд и адаптеры отладчиков

**Актуальное направление:** отдельный Linux-first C++20-бэкенд в ветке `backend/linux`; общие приоритеты, исследования и зависимости описаны в [BACKEND_HANDOFF.md](BACKEND_HANDOFF.md). LLDB остаётся одним из адаптеров (особенно для native macOS), для записи/повтора исследуются rr/GDB, для вычислений и lifetimes — Clang/LLVM-инструментация. Сборка основы и проверка Linux-окружения описаны в [LINUX_BACKEND.md в backend/linux](https://github.com/Tigersmechom/Phantom/blob/backend/linux/docs/LINUX_BACKEND.md). Эта подготовка ещё не подключает реальный отладчик к UI. Codeforces, графы и многопоточность сохранены в поздних этапах.

`src/demo.ts` остаётся отдельным источником **демонстрационных** шагов, переменных и истории. Hover ASM также является макетом. Реальная компиляция в Basic не делает эти данные наблюдениями процесса.

Первый проект предоставляет `window.debuggerApi`: `run`, `step`, `seek`, `restore`, `edit`, `continue`, `pause`, `stop`, `setBreakpoints`, `getState`, `subscribe`. Его сервис исполнения можно подключить через отдельный адаптер в модель phantom, сохранив независимость рендера и исполнения.

При подключении:

1. Разделять живую остановку процесса и просматриваемое наблюдение истории. «Назад» читает запись; `restore` восстанавливает процесс отдельной операцией.
2. Передавать точные 64-битные значения строками. Изменение переменной подтверждать записью в процесс и повторным чтением, а не анимацией.
3. Привязывать сессию к версии исходника, бинарнику, флагам и архитектуре. ARM64/x86-64 уже выбирают реальную сборку; отладочные данные должны относиться к тому же артефакту.
4. Получать hover ASM по исходной строке и DWARF line table. Старый API отдаёт инструкции вокруг PC; произвольная строка требует расширения backend. Пустые строки и комментарии могут не иметь инструкций.
5. Заменить таймер demo подтверждёнными остановками LLDB. Слежение камеры должно получать их идентификаторы, не выводить исполнение из номера строки.
6. При развитии редактора подключить Monaco/clangd для семантики и навигации; 3D остаётся отдельным представлением текста и токенов.

`unreal/` — независимый эксперимент с материалами и геометрией букв. Карта сохранена и проверена; неудачный offscreen-кадр не является превью или подтверждением работающего отладчика.
